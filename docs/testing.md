# StegoCrypt Testing Strategy

## 1. Testing principles

Tests should validate user-visible behavior and security boundaries, not only line coverage.

Each layer is tested independently before the complete workflow is tested.

## 2. Backend unit tests

### Cryptography

Test:

- AES-GCM encrypt/decrypt round trip.
- Empty message handling.
- Unicode message handling.
- Invalid tag rejection.
- Modified ciphertext rejection.
- Modified associated data rejection.
- Nonce length validation.
- Fresh nonce generation.
- X25519 shared-secret agreement.
- Invalid Ed25519 signature rejection.
- Unknown trusted public-key rejection.
- Transcript mismatch rejection.
- Encrypted payload serialization round trip.
- Malformed payload length rejection.

### Steganography

Test:

- QIM embed/extract round trip.
- Multiple image dimensions.
- RGB conversion.
- Alpha channel exclusion.
- Header serialization.
- Header magic and version rejection.
- CRC mismatch rejection.
- Insufficient capacity rejection.
- Maximum payload rejection.
- Invalid image rejection.
- Generated PNG reopening.
- Boundary channel values near 0 and 255.

### Networking

Test:

- Frame encoding and decoding.
- Fragmented length-prefix reads.
- Fragmented frame-body reads.
- Complete writes.
- Unknown frame type rejection.
- Oversized frame rejection.
- Truncated frame rejection.
- Out-of-order chunk rejection.
- Missing chunk rejection.
- Image digest mismatch.
- Timeout handling.
- Clean disconnect handling.

## 3. API tests

Test:

- Health endpoint.
- Session creation.
- Session expiration.
- Invalid bearer token.
- Wrong-role token.
- Invalid and expired join code.
- Join-code reuse.
- Message upload validation.
- Invalid image input.
- Oversized message.
- Oversized image.
- Insufficient image capacity.
- Status transitions.
- Result authorization.
- No plaintext in unverified result responses.
- Safe error response format.

## 4. End-to-end test

The main integration test will:

1. Start a test receiver session.
2. Pair a sender.
3. Generate a deterministic test image.
4. Submit a known message.
5. Run the actual crypto, QIM, and TCP layers.
6. Wait for completion.
7. Retrieve the receiver result.
8. Assert that the recovered message matches the original.
9. Assert that metrics are present.
10. Assert that no secret values appear in logs or status responses.

## 5. Security tests

Security tests must verify:

- A man-in-the-middle identity is rejected.
- An altered signature is rejected.
- A repeated nonce under one key is not generated by the API.
- Payload length cannot trigger excessive allocation.
- TCP frame length cannot bypass limits.
- Session IDs do not authorize requests without tokens.
- Sender tokens cannot retrieve receiver plaintext.
- Authentication failures never expose plaintext.
- CORS does not allow arbitrary origins by default.

## 6. Frontend tests

Frontend tests will use a browser component testing setup such as Vitest and React Testing Library.

Test:

- Navigation between pages.
- Cover image selection and preview.
- Invalid file error.
- Session creation display.
- Join-code submission.
- Status polling.
- Progress timeline.
- Backend error rendering.
- Metric rendering.
- Verified message rendering.
- Rejected message does not render plaintext.

## 7. Performance tests

Performance tests should be repeatable and should record:

- Image dimensions.
- Message size.
- QIM delta.
- Hardware/environment.
- Number of repetitions.
- Average and range of timings.
- Transfer size and throughput.

Performance measurements are evidence for the evaluation dashboard, not pass/fail claims by themselves.

## 8. Planned commands

Backend from the `backend/` directory:

```bash
pytest -q
ruff check app tests
mypy app
```

Frontend:

```bash
cd frontend
npm run lint
npm run typecheck
npm run test
npm run build
```

No command should be described as passing until it has actually been run against the implemented project.
